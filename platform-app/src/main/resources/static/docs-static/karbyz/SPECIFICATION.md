# Спецификация языка Карбыз

| Поле | Значение |
|------|----------|
| Идентификатор языка | Karbyz / Карбыз |
| Версия языка | 1.4 |
| Версия документа | 1.4.2 |
| Статус | нормативный |
| Метаязык синтаксиса | РБНФ |
| Целевая платформа | Watermelon CI |
| Расширение исходных файлов | `.kbz` |
| Кодировка исходного текста | UTF-8 |

Настоящий документ определяет лексику, синтаксис, статическую и динамическую семантику языка Карбыз.
Карбыз — поверхностный синтаксис манифеста пайплайна Watermelon CI (наравне с YAML-формой) и императивных конструкций сценария.

---

## 1. Область применения и соответствие

### 1.1. Область применения

Реализация обязана:

1. анализировать исходный текст на соответствие настоящей спецификации;
2. отображать платформенные конструкции (§10) на единую модель пайплайна платформы;
3. компилировать корректный манифест в Jenkinsfile тем же конвейером, что YAML;
4. при необходимости исполнять программу (динамическая семантика).

### 1.2. Нормативные соглашения

В РБНФ: `"терминал"`; `Нетерминал`; `A | B`; `[ X ]` — опционально; `{ X }` — ≥0 раз; правило заканчивается `.`

Модальности: **должен** / **не должен** / **может**.

### 1.3. Соответствие реализации

Реализация соответствует 1.4, если отвергает нарушения лексики/синтаксиса, выполняет семантические проверки §§4–9, обеспечивает поведение §§5–10, диагностику §12, модель §10 и чеклист §14.

## 2. Лексическая структура

### 2.1. Исходный текст

Исходный текст — последовательность Unicode scalar values в кодировке UTF-8. Байт порядка (BOM) `U+FEFF` в начале файла **может** игнорироваться. Иные кодировки — вне области настоящей спецификации.

### 2.2. Пробельные символы

Символы `U+0020` (пробел), `U+0009` (TAB), `U+000D` (CR), `U+000A` (LF) разделяют лексемы, кроме:

1. внутри строкового литерала (§2.7);
2. внутри многосимвольной лексемы (`<-`, `::`, `==`, `!=`, `<=`, `>=`, `&&`, `||`).

Последовательность пробельных символов эквивалентна одному разделителю. CR+LF считается двумя пробельными, но не создаёт двух границ лексем между собой.

### 2.3. Комментарии

Комментарий начинается с `#` вне строкового литерала и длится до конца строки (не включая LF). Комментарий удаляется до классификации лексем. `#` внутри `"…"` — обычный символ строки.

### 2.4. Классы лексем

| Класс | Определение |
|-------|-------------|
| `keyword` | ключевое слово из §2.6 |
| `ident` | Letter, затем Letter / Digit / `_`; регистр значим |
| `number` | одна или более десятичных цифр `0`–`9` |
| `string` | `"…"`, экранирования: `\\` `\"` `\n` `\t` |
| `assign` | `<-` |
| `open` | `::` |
| `op` | арифметика, сравнения, `&&`, `||`, `!` — см. §2.8 |
| `punct` | `( ) [ ] , .` |

Двухсимвольные лексемы (`<-`, `::`, `==`, `!=`, `<=`, `>=`, `&&`, `||`) распознаются предпочтительно перед односимвольными.

Letter: Unicode-буквы кириллицы и латиницы, допустимые в идентификаторах платформы (без ә ө ү җ ң һ). Digit: `0`–`9`.

### 2.5. Идентификаторы

Регистр значим (`Foo` ≠ `foo`). Идентификатор **не должен** совпадать с ключевым словом после нормализации регистра ключевых слов (§2.6). Длина идентификатора ≥ 1.

### 2.6. Ключевые слова (полный словарь с переводами)

Регистр ключевых слов **не** значим (`Агар` ≡ `агар`). Алфавит ключевых — кириллица/латиница без ә ө ү җ ң һ.

| Обозначение | Перевод | Роль |
|-------------|---------|------|
| `сан` | число | тип: целое |
| `суз` | слово / строка | тип: Unicode-строка |
| `тезма` | ряд / массив | тип: список |
| `логик` | логический | тип: boolean (`дорес`/`ялган`) |
| `дорес` | истина | логическая константа true |
| `ялган` | ложь | логическая константа false |
| `жыелма` | собрание / модуль | единица компиляции |
| `ахыр` | конец | закрытие блока/модуля |
| `::` | открыть блок | начало составного оператора |
| `<-` | присвоить | связывание |
| `агар` | если | условие |
| `булса` | то | then |
| `юкса` | иначе | else |
| `шулай` | пока так | while |
| `вакыт` | время / пока | хвост while |
| `очен` | для | for |
| `да` | и / до | зона for |
| `кадак` | шаг | зона for |
| `эшлама` | работа / функция | объявление функции |
| `кайтар` | вернуть | return |
| `керт` | ввести | stdin |
| `чыгар` | вывести | stdout |
| `озынлык` | длина | длина суз/тезма → сан |
| `хам` | и | логическое И |
| `яки` | или | логическое ИЛИ |
| `тугел` | не | логическое НЕ |
| `этап` | этап | стадия CI |
| `башкар` | исполнить | команда оболочки |
| `сервер` | сервер / узел | целевой хост |

### 2.7. Строковые литералы

Строка: `"` содержимое `"`. Незакрытый литерал до EOF — ошибка лексера (`лексер`).

| Последовательность | Значение |
|--------------------|----------|
| `\\` | U+005C |
| `\"` | U+0022 |
| `\n` | U+000A |
| `\t` | U+0009 |
| иной `\X` | ошибка лексера |

Строка может быть пустой: `""`.

### 2.8. Операторы (класс `op`)

| Лексема | Имя | Примечание |
|---------|-----|------------|
| `+` `-` `*` `/` `%` | арифметика | также унарные `+` `-` |
| `==` `!=` `<` `<=` `>` `>=` | сравнение | → `логик` |
| `&&` | логическое И (ASCII) | синоним `хам` |
| `||` | логическое ИЛИ (ASCII) | синоним `яки` |
| `!` | логическое НЕ (ASCII) | синоним `тугел` |

Ключевые `хам` / `яки` / `тугел` — класс `keyword`, не `op`; семантика совпадает с ASCII-формами (§5.5).

### 2.9. Максимальный мунк (longest match)

Лексер применяет правило наибольшего совпадения: при неоднозначности выбирается самая длинная лексема. Пример: `<=` — одна лексема, не `<` затем `=`.

## 3. Синтаксис программы

```
жыелма ModuleName ::
  { DeclarationOrStatement }
ахыр жыелма .
```

Элементы обрабатываются в порядке записи. Все `эшлама` модуля регистрируются до исполнения прочих операторов верхнего уровня. Полная РБНФ — §11.

### 3.1. Структура модуля

1. Заголовок `жыелма` Ident `::`.
2. Тело: ноль или более объявлений/операторов.
3. Закрытие `ахыр жыелма` `.` — точка обязательна.

Отсутствие точки после `ахыр жыелма` — ошибка синтаксиса.

### 3.2. Порядок связывания

Перед исполнением верхнего уровня строится таблица функций (§7, §9). Операторы `эшлама` на верхнем уровне **не** исполняются как процедуры при проходе тела — только регистрируются.

## 4. Система типов

### 4.1. Типы значений

| Тип | Ключевое слово | Носитель | Литералы | По умолчанию |
|-----|----------------|----------|----------|--------------|
| целое | `сан` | целое ≥32 бит | `0`, `42` | `0` |
| строка | `суз` | Unicode | `"…"`, `""` | `""` |
| массив | `тезма` | упорядоченный список, индекс с 0 | `[…]`, `[]` | `[]` |
| логический | `логик` | `дорес` или `ялган` | `дорес`, `ялган` | `ялган` |

### 4.2. Тип `логик` — как получить логическое значение

Тип переменной `логик` объявляется явно. Значение носителя — только `дорес` (истина) или `ялган` (ложь).

**Способы получить значение типа `логик`:**

| Способ | Пример | Результат |
|--------|--------|-----------|
| литерал | `логик f <- дорес` | `дорес` |
| литерал | `логик f <- ялган` | `ялган` |
| default | `логик f` | `ялган` |
| сравнение | `логик ok <- n > 0` | `дорес` или `ялган` |
| связка | `логик ok <- a хам b` | `дорес` или `ялган` |
| отрицание | `логик ok <- тугел ready` | `дорес` или `ялган` |
| ввод | `керт (логик f)` | разбор строки (§6.10) |
| вызов | `логик ok <- проверка (x)` | тип `кайтар` должен быть `логик` |

**Запрещено** присваивать в `логик` значение `сан`/`суз`/`тезма` без явного сравнения:

```
логик f <- 1        # ошибка семантики
логик f <- n > 0    # допустимо
```

### 4.3. Совместимость присваивания

| Левая | Правая | Результат |
|-------|--------|-----------|
| `сан` | `сан` | ок |
| `суз` | `суз` | ок |
| `тезма` | `тезма` | ок |
| `логик` | `логик` | ок |
| иначе | | ошибка семантики/исполнения |

Неявные преобразования запрещены, кроме конкатенации `+` при участии `суз` (§5.4).

### 4.4. Логический контекст (условия)

В `агар` / `шулай` / `очен` Cond приводится к логическому:

| Значение | Истина? |
|----------|---------|
| `дорес` | да |
| `ялган` | нет |
| `сан` = 0 | нет |
| `сан` ≠ 0 | да |
| `суз` длины 0 | нет |
| иная `суз` | да |
| `тезма` длины 0 | нет |
| иная `тезма` | да |

`логик` в Cond используется напрямую (без дополнительного приведения).

### 4.5. Объекты среды исполнения

`Module`, `Function`, `Env` (имя → `(Type, Value)`), `Value`, `Stage`, `Host`, `Command`, `Diagnostic`.

## 5. Выражения

### 5.1. Приоритет (↑ выше)

| Ур. | Операторы | Ассоц. | Тип результата |
|-----|-----------|--------|----------------|
| 1 | `яки` / `||` | лево | `логик` |
| 2 | `хам` / `&&` | лево | `логик` |
| 3 | `тугел` / `!` | право | `логик` |
| 4 | `==` `!=` `<` `<=` `>` `>=` | лево | `логик` |
| 5 | `+` `-` | лево | `сан` или `суз` |
| 6 | `*` `/` `%` | лево | `сан` |
| 7 | унарные `+` `-` | право | `сан` |
| 8 | вызов, индекс, первичные | — | по контексту |

Скобки `( Expr )` поднимают приоритет до первичного.

### 5.2. Арифметика: что с чем складывать / умножать

Нормативное правило: **`-` `*` `/` `%` и унарные `+` `-` допустимы только для `сан` × `сан`**. Оператор **`+`** — либо арифметика двух `сан`, либо конкатенация, если участвует `суз` (§5.4).

#### 5.2.1. Матрица `+` (сложение / конкат)

| L \\ R | `сан` | `суз` | `логик` | `тезма` |
|--------|-------|-------|---------|---------|
| `сан` | `сан` (арифм.) | `суз` (конкат) | **ошибка** | **ошибка** |
| `суз` | `суз` (конкат) | `суз` (конкат) | `суз` (конкат) | `суз` (конкат) |
| `логик` | **ошибка** | `суз` (конкат) | **ошибка** | **ошибка** |
| `тезма` | **ошибка** | `суз` (конкат) | **ошибка** | **ошибка** |

#### 5.2.2. Матрица `-` `*` `/` `%`

Для **каждого** из `-`, `*`, `/`, `%` матрица одинакова:

| L \\ R | `сан` | `суз` | `логик` | `тезма` |
|--------|-------|-------|---------|---------|
| `сан` | `сан` | **ошибка** | **ошибка** | **ошибка** |
| `суз` | **ошибка** | **ошибка** | **ошибка** | **ошибка** |
| `логик` | **ошибка** | **ошибка** | **ошибка** | **ошибка** |
| `тезма` | **ошибка** | **ошибка** | **ошибка** | **ошибка** |

Унарные `+e` / `-e`: операнд **должен** быть `сан`, иначе ошибка. Результат — `сан`.

Деление `/` — усечение к нулю. `/ 0` и `% 0` — ошибка исполнения (даже при типах `сан`×`сан`).

| Выражение | Результат / отказ |
|-----------|-------------------|
| `3 + 4` | `7` (`сан`) |
| `"a" + 1` | `"a1"` (`суз`) |
| `1 + "a"` | `"1a"` (`суз`) |
| `дорес + 1` | ошибка |
| `7 / 2` | `3` |
| `-7 / 2` | `-3` |
| `7 % 2` | `1` |
| `1 / 0` | ошибка исполнения |
| `"a" * 2` | ошибка |
| `[1] + [2]` | ошибка (нет `суз`) |
| `"x" + [1,2]` | `суз` (конкат с печатной формой массива) |

### 5.3. Сравнения → `логик`

Сравнивать можно **только одинаковые носители** (кроме `тезма` — сравнения массивов запрещены).

| Операция | L | R | Результат |
|----------|---|---|-----------|
| `==` `!=` | `сан` | `сан` | `логик` |
| `==` `!=` | `суз` | `суз` | `логик` |
| `==` `!=` | `логик` | `логик` | `логик` |
| `<` `<=` `>` `>=` | `сан` | `сан` | `логик` |
| `<` `<=` `>` `>=` | `суз` | `суз` | `логик` (лексикографически) |
| любое сравнение | `тезма` | * | **ошибка** |
| любое сравнение | разные типы | | **ошибка** |

| L \\ R для `==` | `сан` | `суз` | `логик` | `тезма` |
|-----------------|-------|-------|---------|---------|
| `сан` | ок → `логик` | ошибка | ошибка | ошибка |
| `суз` | ошибка | ок → `логик` | ошибка | ошибка |
| `логик` | ошибка | ошибка | ок → `логик` | ошибка |
| `тезма` | ошибка | ошибка | ошибка | ошибка |

Для `<` `<=` `>` `>=` допустимы только `сан`×`сан` и `суз`×`суз` (остальные клетки — ошибка).

### 5.4. Конкатенация (`+` с участием `суз`)

Если **хотя бы один** операнд `+` имеет тип `суз`, операция — конкатенация → `суз` (см. матрицу §5.2.1). Второй операнд приводится к тексту:

| Тип | Печатная форма для конката |
|-----|----------------------------|
| `сан` | десятичная запись |
| `суз` | содержимое |
| `логик` | `дорес` / `ялган` |
| `тезма` | стабильная печатная форма реализации |

Если **ни один** операнд не `суз`, `+` — только арифметика `сан`×`сан` (§5.2.1).

### 5.5. Логические связки → `логик`

| Операция | Семантика |
|----------|-----------|
| `e1 хам e2` / `&&` | если e1 ложен в §4.4 — `ялган` (e2 не вычисляется); иначе логический контекст e2 как `логик` |
| `e1 яки e2` / `||` | если e1 истинен — `дорес` (e2 не вычисляется); иначе контекст e2 |
| `тугел e` / `!` | `дорес`, если e ложен; иначе `ялган` |

**Примеры отказов / короткого замыкания:**

```
логик a <- ялган
логик b <- a хам (1 / 0)   # b = ялган; деление не выполняется
логик c <- дорес яки (1 / 0)  # c = дорес; деление не выполняется
логик d <- 1               # ошибка: сан → логик запрещён
```

### 5.6. Индексация

`a[i]`: `a` — `тезма`, `i` — `сан`, `0 ≤ i < озынлык(a)`. Иначе ошибка. Тип результата — носитель элемента.

### 5.7. Вызов

`f(…)` — §7. Арность и типы параметров должны совпадать.

### 5.8. `озынлык(e)`

Для `суз`|`тезма` → `сан`. Иначе ошибка.

### 5.9. Литерал массива

`[ e1, … ]` → `тезма`.

### 5.10. Условные выражения (`Cond`)

`Cond` в `агар` / `шулай` / `очен` — обычное `Expr`. Отдельного синтаксиса нет.

| Вид | Пример | Правило истинности |
|-----|--------|-------------------|
| `логик`-переменная | `флаг` | значение `дорес`/`ялган` |
| сравнение | `n < 10` | результат `логик` |
| связка | `a хам b` | §5.5 |
| отрицание | `тугел ready` | §5.5 |
| `сан` / `суз` / `тезма` | `счётчик` | §4.4 |

Ошибка внутри Cond (деление на 0, плохой индекс) — Cond не завершается; тело не выполняется.

### 5.11. Сводная таблица операция → типы → результат

Краткая выжимка; полные матрицы — §5.2–§5.4.

| Операция | Допустимые L × R | Результат | Иначе |
|----------|------------------|-----------|-------|
| `+` | `сан`×`сан` | `сан` | — |
| `+` | есть `суз` (любая сторона) | `суз` | — |
| `+` | прочие пары без `суз` | — | **ошибка** |
| `-` `*` `/` `%` | только `сан`×`сан` | `сан` | **ошибка** |
| унарные `+` `-` | `сан` | `сан` | **ошибка** |
| `==` `!=` | `сан`×`сан`, `суз`×`суз`, `логик`×`логик` | `логик` | **ошибка** |
| `<` `<=` `>` `>=` | `сан`×`сан`, `суз`×`суз` | `логик` | **ошибка** |
| `хам` `яки` | два Expr (через §4.4) | `логик` | — |
| `тугел` `!` | один Expr (§4.4) | `логик` | — |
| `a[i]` | `тезма` × `сан` | элемент | **ошибка** |
| `озынлык` | `суз` или `тезма` | `сан` | **ошибка** |
| `дорес` `ялган` | — | `логик` | — |
| `[…]` | — | `тезма` | — |

## 6. Операторы

### 6.1. Блок

`:: { Statement } ахыр` — вложенная `Env`.

### 6.2. Объявление

Синтаксис: `Type Ident [ <- Expr ]`

| Предусловие | Постусловие / отказ |
|-------------|---------------------|
| имя свободно в текущей Env | связывание `(Type, Value)` |
| имя уже связано здесь | ошибка семантики |
| есть `Expr`, тип совместим (§4.3) | Value = результат Expr |
| нет `Expr` | Value = default типа |

Default: `сан`→`0`, `суз`→`""`, `тезма`→`[]`, `логик`→`ялган`.

### 6.3. Присваивание

Синтаксис: `Ident <- Expr` или `Ident [ Expr ] <- Expr`

| Предусловие | Постусловие / отказ |
|-------------|---------------------|
| Ident объявлен (поиск §8) | Value обновлён |
| не объявлен | ошибка |
| индексная форма, Ident не `тезма` | ошибка |
| индекс вне `[0, озынлык)` | ошибка исполнения |
| тип правой несовместим | ошибка |

### 6.4. `агар`

```
агар ( Cond ) булса :: ThenPart [ юкса :: ElsePart ] ахыр
```

| Предусловие | Поведение |
|-------------|-----------|
| Cond вычислен (§5.10) | Then при истине §4.4 |
| Cond ложен, есть `юкса` | Else |
| Cond ложен, нет `юкса` | no-op |
| ошибка в Cond | Then/Else не выполняются |

Each of Then/Else — новая вложенная Env.

### 6.5. `шулай`

```
шулай ( Cond ) вакыт :: Body ахыр
```

| Шаг | Действие |
|-----|----------|
| 1 | вычислить Cond |
| 2 | если ложен — выход |
| 3 | Body в новой Env |
| 4 | goto 1 |

### 6.6. `очен`

```
очен ( Init да Cond кадак Step ) :: Body ахыр
```

1. Init (объявление или присваивание), если задан — один раз.  
2. Пока Cond истинен: Body (новая Env), затем Step (присваивание).

Пустые Init/Step допустимы синтаксически, если грамматика допускает опущение (§11).

### 6.7. `кайтар`

`кайтар [ Expr ]` — **только** внутри `эшлама`. Вне функции — ошибка семантики. Завершает вызов; значение — Expr или «пусто».

### 6.8. Вызов как оператор

`Ident ( … )` как Statement — вычисляет вызов и отбрасывает результат.

### 6.9. `чыгар`

Печать аргументов через один пробел, затем перевод строки.

| Тип аргумента | Печатная форма |
|---------------|----------------|
| `сан` | десятичная запись |
| `суз` | содержимое |
| `логик` | `дорес` / `ялган` |
| `тезма` | реализация **должна** выбрать стабильную текстовую форму |

### 6.10. `керт`

`керт ( Type Ident )` — читает **одну** строку stdin (без завершающего LF в значении). Ident объявляется или должен быть совместим с Type в текущей Env (как объявление).

| Type | Разбор | Ошибка |
|------|--------|--------|
| `сан` | десятичное целое, без пробелов по краям | неверный формат |
| `суз` | строка как есть | — |
| `логик` | `дорес` / `ялган` / `1` / `0` (регистр ключей не значим) | иначе |
| `тезма` | не поддерживается | ошибка семантики |

EOF до строки — ошибка «конец ввода».

### 6.11. Платформенные операторы

§10 (`этап`, `башкар`, `сервер`).

---

## 7. Функции

```
эшлама Name ( [ Type Ident { , Type Ident } ] ) :: Body ахыр
```

Имя уникально. Параметры — локальная Env. Арность и типы аргументов = параметры. Без `кайтар` результат пуст.

---

## 8. Области видимости

Поиск: текущая Env → родители → глобальная. Присваивание — ближайшее связывание. Необъявленное имя — ошибка. Параметры и локальные скрывают внешние.

---

## 9. Модуль и точка входа

1. Построить таблицу функций.  
2. Исполнить операторы верхнего уровня (не `эшлама`).  
Отдельного `main` нет.

## 10. Манифест Watermelon CI

Карбыз и YAML — два синтаксиса одной модели.

| Карбыз | Смысл | YAML |
|--------|-------|------|
| `жыелма Name` | имя пайплайна | `name:` |
| `этап "s" :: … ахыр` | стадия | `jobs.*.stage` + `script` |
| `башкар expr` | команда (`суз`) | элемент `script` |
| `сервер "h" :: … ахыр` | узел | stage `host-h` |

Целевой артефакт CI — Declarative Jenkinsfile.

## 11. Нормативная РБНФ

```
Program = "жыелма" Ident "::" { DeclOrStmt } "ахыр" "жыелма" "." .
DeclOrStmt = VarDecl | FuncDecl | Statement .
VarDecl = Type Ident [ "<-" Expr ] .
Type = "сан" | "суз" | "тезма" | "логик" .
FuncDecl = "эшлама" Ident "(" [ Param { "," Param } ] ")" Block .
Param = Type Ident .
Statement = VarDecl | Assign | IfStmt | WhileStmt | ForStmt
  | ReturnStmt | CallStmt | PrintStmt | InputStmt
  | StageStmt | RunStmt | HostStmt .
Block = "::" { Statement } "ахыр" .
Assign = Ident [ "[" Expr "]" ] "<-" Expr .
IfStmt = "агар" "(" Expr ")" "булса" "::" { Statement }
         [ "юкса" "::" { Statement } ] "ахыр" .
WhileStmt = "шулай" "(" Expr ")" "вакыт" Block .
ForStmt = "очен" "(" ForInit "да" Expr "кадак" ForStep ")" Block .
ForInit = [ Type Ident "<-" Expr | Ident "<-" Expr ] .
ForStep = [ Ident "<-" Expr ] .
ReturnStmt = "кайтар" [ Expr ] .
CallStmt = Ident "(" [ Expr { "," Expr } ] ")" .
PrintStmt = "чыгар" "(" [ Expr { "," Expr } ] ")" .
InputStmt = "керт" "(" Type Ident ")" .
StageStmt = "этап" StringLit Block .
RunStmt = "башкар" Expr .
HostStmt = "сервер" StringLit Block .
Expr = OrExpr .
OrExpr = AndExpr { ("яки" | "||") AndExpr } .
AndExpr = NotExpr { ("хам" | "&&") NotExpr } .
NotExpr = ("тугел" | "!") NotExpr | RelExpr .
RelExpr = AddExpr { ("=="|"!="|"<"|"<="|">"|">=") AddExpr } .
AddExpr = MulExpr { ("+"|"-") MulExpr } .
MulExpr = Unary { ("*"|"/"|"%") Unary } .
Unary = ("+"|"-") Unary | Primary .
Primary = Ident [ "(" [ Expr { "," Expr } ] ")" | "[" Expr "]" ]
  | Number | StringLit | "дорес" | "ялган"
  | "[" [ Expr { "," Expr } ] "]" | "(" Expr ")" | "озынлык" "(" Expr ")" .
```

## 12. Транслятор: фазы и проходы

| № | Фаза | Вход | Выход | Отказ |
|---|------|------|-------|-------|
| 1 | Лексер | UTF-8 текст | поток лексем | незакрытая строка, плохой escape |
| 2 | Парсер | лексемы | AST | неожиданная лексема, EOF |
| 3 | Семантика | AST | аннотированный AST | типы, повторные имена, `кайтар` вне функции |
| 4a | Исполнение | AST | эффекты I/O / команд | `/0`, индекс, EOF `керт` |
| 4b | Компиляция CI | AST манифеста | Jenkinsfile | только после успеха 1–3 |

### 12.1. Порядок

Лексер и парсер образуют однопроходный конвейер «текст → AST». Семантика — отдельный проход по AST. Исполнение и компиляция Jenkinsfile — альтернативные потребители одного аннотированного AST (не «однопроходный сразу в машинный код»).

### 12.2. Диагностика

Каждое сообщение **должно** содержать:

1. фазу: `лексер` | `синтаксис` | `семантика` | `исполнение`;
2. позицию `строка:столбец` (1-based), насколько применимо;
3. человекочитаемый текст.

При ошибке фаз 1–3 Jenkinsfile **не** строится. Код завершения процесса ≠ 0.

### 12.3. Идемпотентность компиляции

Два запуска компиляции на одном и том же исходном тексте при отсутствии ошибок **должны** давать эквивалентный Jenkinsfile (допустимы отличия в незначащих пробелах, если инструмент их нормализует явно).
